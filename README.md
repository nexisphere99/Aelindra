# AELINDRA   The Rite of Becoming

Twine 2 / SugarCube 2.37 project, compiled with [Tweego](https://www.motoslave.net/tweego/).

## Project layout

```
AELINDRA/
├── index.html          ← compiled game (generated by build.sh   open this to play)
├── build.sh             ← compiles src/ into index.html
├── src/                 ← all Twee/CSS/JS source, fed to tweego
│   ├── config/          ← StoryTitle, StoryData, StoryInit, StoryInterface, PassageHeader
│   ├── ui/               ← stylesheet.css, script.js, widgets.tw, fonts/
│   ├── systems/          ← objectives / inventory / wardrobe / time / stat-check / portrait stubs
│   └── passages/
│       ├── title-screen.tw, credits.tw
│       └── days/         ← day content goes here, one folder per day
└── assets/               ← images & audio, OUTSIDE src/ on purpose
    ├── images/{ui,portraits,locations,npcs}/
    └── audio/{ambient,sfx}/
```

**Assets live outside `src/`.** Tweego only compiles `.tw`/`.css`/`.js` files
under `src/` into `index.html`; it never touches `assets/`. Images are
referenced by relative path at runtime (e.g. `assets/images/portraits/...`),
so the compiled HTML stays lean instead of ballooning with embedded
base64 art.

## Building

```bash
./build.sh          # one-off build → index.html
./build.sh watch     # rebuild automatically whenever src/ changes
```

Requires `tweego` on your `PATH` with the `sugarcube-2` story format
installed (already the case in this environment   SugarCube 2.37.3).

After building, open `index.html` directly in a browser to play.

## What's implemented (initial setup)

- Three-panel layout: left sidebar (stats/time/objectives/gold) | center
  passage | right sidebar (MC portrait, name/title, body stats, outfit,
  bonds   the latter three hidden until unlocked).
- Medieval dark-fantasy theme (Cinzel + Cormorant Garamond, gold/purple/
  stone palette), fully responsive (right sidebar hides <1100px, left
  sidebar collapses to a horizontal bar <800px).
- All global state in `StoryInit.tw`.
- `PassageHeader.tw` calls `updateSidebars()` on every passage render.
- Portrait system with graceful placeholder fallback when an art file
  doesn't exist yet (`getPortraitForState()` in `script.js`).
- Widgets: `<<addObjective>>`, `<<completeObjective>>`, `<<statChange>>`
  (with toast notification), `<<updatePortrait>>`, `<<addItem>>`,
  `<<hasItem>>`, `<<speak>>`, `<<advanceTime>>`.
- Title screen → "Begin" goes straight into Day -2 (the shared prologue  
  identical for both routes). There is no upfront Female/Futanari choice;
  `$gamePath` stays `"none"` until Day 0 content sets it based on the
  choices the player actually makes.

## Day content status

- **Day -2 ("The Summons")** — fully built. Hub, 7 sub-hubs, 6 main scenes,
  14 optional NPC encounters, plus two pre-transformation sexual scenes: a
  solo scene and a bathhouse encounter with a new recurring NPC, Handmaiden
  Lissara (`npc/day-2_scene_masturbation.tw`, `npc/day-2_scene_bath.tw` →
  `day-2_scene_bath_sexual.tw`).
- **Day -1 ("The Arguments")** — fully built. Hub, 8 sub-hubs (including the
  Moonspire Tower, unlocked after the Queen scene, with its own purple
  `.loc-new` accent), 5 main scenes, 12 optional NPC encounters (6 of them
  gated behind whether the player met the matching Day -2 NPC), plus four
  pre-transformation sexual/anxiety scenes: a solo scene, a full encounter
  with a new recurring NPC (Handmaiden Sera), an intrusive-thought insert
  into the Queen argument, and a fantasy scene after the training-yard rage
  session, plus an added conversation with Rowan about desire across the
  transformation.
- **Day 0 ("The Rite")** — fully built. This is the day the open world
  closes: a morning hub (chambers, Queen's farewell, corridors, training
  yard, kitchens, library, gardens, servants, Moonspire lower levels — 11
  optional NPC farewells plus two solo body-anxiety scenes and a MAIN scene,
  the Queen's parting gift of two companions) followed by a **point-of-no-
  return bridge** with its own confirmation screen and unfinished-farewells
  checklist. Crossing it clears the hub for good and the game goes fully
  linear: bridge → an in-story path choice (Complete / Partial
  transformation) → the ritual scene itself → a void transition → Day 1.
  **The two paths permanently diverge at the path choice and never merge
  again** — separate ritual scenes, separate void transitions, separate Day
  1 landing hubs (`day1_hub.tw` for the female route, `day1_hub_futa.tw`
  for the futa route), by design, per the source material's own note that
  post-transformation content can't be a find-and-replace between routes.
- **Day 1 onward** — placeholder hubs only (one per route), confirming the
  pipeline lands correctly coming out of both versions of the Rite.

Each day's own `day{N}Init` widget owns that day's scene/NPC flags and is
called from the *previous* day's sleep-transition/bridge passage —
`StoryInit.tw` only holds state that persists across the whole game (stats,
affinities, and the sexual-content baseline flags —
`$maleBaselineEstablished`, `$seraEncountered`/`$seraIntimate`,
`$lissaraEncountered`, `$penetrationAnxiety`, `$queensGiftAccepted`,
`$veylaEncountered`/`$sennaEncountered` — since Day 1+ body-discovery scenes
are meant to reference them for contrast).

### Note on `StoryCaption.tw`

The setup prompt's file list mentions `StoryCaption.tw` for left-sidebar
content, but that content is fully implemented inside `StoryInterface.tw`
already (and SugarCube's default UI bar   where `StoryCaption` would
normally render   is hidden via CSS). Adding a separate `StoryCaption.tw`
would just be dead code, so it was intentionally left out.

### Fonts

Cinzel/Cormorant Garamond currently load from Google Fonts via `@import`
in `stylesheet.css`. `src/ui/fonts/README.md` has instructions for
switching to fully offline local `@font-face` files if you need the game
to run with no internet connection.
